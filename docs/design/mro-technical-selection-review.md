## 1. 模型选择结论

**首版保留正则化逻辑回归与 LightGBM 的对比方案。CatBoost 作为优先扩展候选，最终使用哪个模型，由相同划分和警报预算下的验证结果决定。**

当前数据版本 `0.1.0` 的清单记录了 60 架飞机、757 个部件、114,998 条快照、436 次非计划拆换，成熟快照正例率为 2.31%。同一部件和拆换事件对应多条快照，因此模型复杂度和评估可信度需要结合飞机组、部件和事件数量判断。数据规模见 早期清单 `data/generated/mock_v0_1_0/manifest.json`；当前数据见 [数据字典](../../DATASET.md)。

输入是传感器滚动统计、使用情况、类别属性、故障计数和维修历史组成的混合表格特征。这种输入适合先比较线性模型与梯度提升树。公开表格基准也支持将树模型作为强候选，但模型表现仍取决于具体数据和调参条件。[表格数据基准研究](https://arxiv.org/abs/2305.02997)

| 模型 | 本项目中的角色 | 选择理由 | 需要验证的内容 |
| --- | --- | --- | --- |
| 正则化逻辑回归 | 必选基线，也可成为最终模型 | 用于检验线性信号能达到的效果，系数便于检查，训练与推理成本低 | 非线性趋势、交互及未知类别是否导致性能损失 |
| LightGBM | 首版主候选 | 对应混合表格特征，支持非线性、交互、数值缺失与类别特征 | 事件级召回、校准、未见实体泛化及时间稳定性 |
| CatBoost | 首选扩展候选 | 类别及类别组合较重要时，可检验其类别处理方式是否带来收益 | 与 LightGBM 在相同业务约束下的实际差异 |

LightGBM 的缺失与类别处理能力见 [官方文档](https://lightgbm.readthedocs.io/en/stable/Advanced-Topics.html)。当前 [README](../../README.md) 说明模型训练尚未实现，现阶段的结论是模型适配性判断；模型优劣需要通过下述比较流程形成证据。

## 2. 其他模型是否值得采用

| 候选方案 | 值得评估的条件 | 本次建议 |
| --- | --- | --- |
| CatBoost | 型号、批次、故障类别等特征贡献明显，类别组合复杂 | 排在扩展实验首位；先完成现有两模型，再按验证误差分析决定是否加入 |
| XGBoost | 团队已有训练、部署经验，或希望增加另一种提升树实现作对照 | 可替换为主候选或增加对照，替换依据采用业务验证结果 |
| 随机森林 / ExtraTrees | 希望增加训练配置较简单的树集成对照 | 作为低优先级实验，先评估现有模型的误差来源 |
| 离散时间生存模型 / 竞争风险模型 | 真实数据删失明显、需要多个预测窗口，或计划拆换大量改变后续风险观察 | 达到条件后比较，先明确预测目标和结局处理方式 |
| LSTM / TCN / 时序 Transformer | 获取高频原始轨迹，滚动统计丢失了重要时序模式，且有足够多的独立事件 | 用于后续轨迹建模实验；当前聚合特征方案先以表格模型完成验证 |
| TabPFN 等表格基础模型 | 希望探索预训练模型，且能满足指定权重版本的算力、授权和交付条件 | 列为探索候选，单独记录模型权重、计算成本和可复现配置 |

### 2.1 CatBoost 的加入方式

CatBoost 的直接价值是对类别及其组合进行模型内部处理。若加入，直接传入声明为类别的字段，类别缺失统一映射为字符串标记，数值缺失按其数值缺失机制处理。[类别处理](https://catboost.ai/docs/en/features/categorical-features)、[缺失处理](https://catboost.ai/docs/en/concepts/algorithm-missing-values-processing)

训练数据按时间排序，审查类别统计是否使用了样本当时尚未成熟的标签。`has_time` 可用于保留输入顺序，但实体隔离、标签成熟和时间切分仍由项目的数据流程保证。[时间顺序参数](https://catboost.ai/docs/en/references/training-parameters/common#has_time)

### 2.2 XGBoost 和 TabPFN 的选择依据

XGBoost 已支持原生类别特征；比较时应明确类别配置和模型保存格式。[官方类别文档](https://xgboost.readthedocs.io/en/stable/tutorials/categorical.html)

TabPFN 的数据规模能力随权重版本变化，应按选定版本核对。当前官方项目推荐 GPU，代码与模型权重分别授权；引入时要固定权重版本、文件哈希、使用权限和本地推理配置。[官方项目说明](https://github.com/PriorLabs/TabPFN)

这两类候选均使用本项目的实体、时间和事件评估流程，公开表格基准中的表现只能作为选型参考。

### 2.3 生存分析的启动条件

首版用二分类完成固定 30 循环窗口的 PoC 是合理选择。真实数据阶段需要先确定目标：现行维修策略下实际发生非计划拆换的概率，或假设持续在役时的潜在失效风险。两者对应的标签与干预处理不同。

计划拆换会终止本次装机区间内继续观察非计划拆换的机会。若估计现行策略下的实际拆换概率，可考虑将计划拆换作为竞争结局；若处理为删失，需要检查删失与退化状态的关联。当前数据字典将窗口内计划拆换列为删失并排除，应记录由此形成的评估人群，并在真实数据阶段检查选择偏差。[竞争风险方法说明](https://scikit-survival.readthedocs.io/en/stable/user_guide/competing-risks.html)

## 3. 判断“更优模型”的比较规则

1. 所有候选使用相同的原始数据版本、快照、标签、特征定义和外层划分。预处理可按模型特点配置。
2. 使用有限、可复现的调参预算，记录搜索空间、随机种子、训练耗时及失败实验。类别权重候选包含不加权配置。
3. 在验证阶段，为每个候选拟合校准器并选择警报策略，使用同一轮次定义和预算规则。
4. 首先比较满足警报预算时的事件级召回率，再检查检出提前量、误报负担、校准、分群稳定性与推理成本。
5. 主要指标按连通组进行聚类 bootstrap；时间稳定性采用保留实体轨迹的时间块或滚动窗口分析，报告实际事件数和置信区间。
6. 验证结果接近时，优先选择校准、稳定性和维护成本更符合业务要求的模型。逻辑回归也具有成为最终模型的资格。
7. 在查看最终测试结果前确定模型和完整策略。测试阶段核验 `event_recall >= 0.80` 与警报预算是否同时成立。

建议记录的比较表字段：模型、划分版本、事件数、事件召回率及区间、每轮警报率、总体警报率、误报、PR-AUC、Brier Score、提前量、训练与推理耗时。

合成数据用于验证流程和压力场景。真实机队效果需要在真实数据上独立验证。

## 4. 优先修订的数据与评估方案

### 4.1 数据划分：统一实体用途与全局时间窗口

对应原设计第 6.1、6.2、6.3 节及实施待办 C。

现有第 3 步先分配训练、验证和测试连通组，第 4 步又在每个分区内部重新三分，样本用途存在歧义。建议改为：

1. 用飞机与部件流转关系生成连通组，报告组数、组规模、最大组占比和事件分布。
2. 将完整连通组分配到外层训练、验证、测试用途；主评估中三者的飞机与部件集合互斥。
3. 设定全局时间截点。训练用途只取早期样本，验证用途取后续样本，测试用途取更晚样本，其余记录明确标注用途或排除原因。
4. 每次拟合仅使用当时已成熟的标签，剔除跨边界且结局尚不可知的记录。30 循环的成熟条件按部件使用轨迹转换为时间条件。
5. 训练分区内部进行受实体和时间约束的调参；验证前段用于校准，后段用于选择警报策略。校准标签须在策略评估起点前可用。
6. 若独立事件不足，采用符合上述约束的交叉拟合，保存每条折外预测的训练来源、拟合时点和用途。

`TimeSeriesSplit` 只提供时间顺序索引，`gap` 表示样本数。项目需要自定义划分清单与断言来表达飞机、部件、事件和飞行循环约束。[接口说明](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)

验收：外层实体交集为空；时间顺序成立；特征与标签可用时间合法；同一拆换事件不会跨越外层用途；连通组不足时明确报告划分不可行。

补充滚动评估需声明评估对象：既有机队的未来风险可允许同一实体出现在过去训练和未来评估中，结果单独报告；主评估继续用于检验未见飞机和部件的泛化。

### 4.2 数据模型：增加装机区间与可用时间

对应原设计第 3、4、5 节及实施待办 B、D。

| 字段或约定 | 建议 |
| --- | --- |
| `installation_id` | 标识一次装机至拆下的区间，支持部件跨飞机流转及维修后重新装机 |
| `aircraft_total_cycles` | 明确飞机累计循环 |
| `component_total_cycles` | 明确部件全寿命累计循环 |
| `cycles_since_install` | 明确本次装机后的使用循环 |
| `event_time` | 事件实际发生时间 |
| `available_at` | 系统当时可读取该条记录的时间 |
| `label_available_at` | 标签结局能够合法确定的时间 |

数据字典目前已将 `snapshot_cycle` 定义为飞机累计循环，应同步到设计稿。当前 `component_cycles` 表示自装机以来循环；引入多次装机后，需要区分部件全寿命与本次装机计数。

历史特征同时满足 `event_time <= snapshot_time` 和 `available_at <= snapshot_time`。修改后的维修记录若覆盖旧值，还需要保留历史版本以重建当时可见内容。

验收：同一部件两次装机有不同区间键；累计循环与装机计数可追溯；迟报记录不会提前进入特征；相同历史时点可重建相同输入。

### 4.3 警报决策：明确每轮硬预算及容量保护

对应原设计第 3.3、7.2、8.2、10 节及实施待办 A、F、H。

先固定评分批次定义，例如每日统一的机队评分批次。当前模拟数据每 5 个循环生成一次快照，需要定义快照到业务批次的映射。

固定阈值在验证集满足预算，未来评分分布变化后仍可能超额。若业务要求每轮严格不超过 5%，建议冻结以下策略：

1. 以该轮参评在役部件数 `N` 计算容量 `K = floor(0.05 * N)`。
2. 选出风险超过最低阈值的部件，按冻结规则抑制重复警报，再按风险排序，最多发出 `K` 次警报。仅对实际发出的警报更新抑制状态。
3. 冻结并列分数、重复警报抑制、解除抑制及小批次处理规则。少于 20 个部件时，严格按此公式会得到零容量，需在设计中明确批次粒度。
4. 输出因容量限制未进入队列的部件数，并以实际发出的警报计算事件检出和提前量。
5. 对抑制前警报、抑制后警报、容量截断后的最终警报分别留痕。

报告逐轮警报率、最大值及超限轮次数，同时报告按部件轮次加权的总体警报率。标签尚未成熟的警报仍计入警报负担，其误报结局标为待定。

验收：若采用硬上限，所有轮次均满足容量规则；最终召回按完整策略回放计算；模型分数、警报决策和容量延后原因均可追溯。

### 4.4 概率校准与类别权重：指定默认方法和数据用途

对应原设计第 5.1、7.2 节及实施待办 E。

- 将 Platt/sigmoid 设为默认校准候选，保留未校准结果作为对照。
- 数据充分后比较 isotonic，检查独立事件数、分数区间覆盖、重复快照相关性和时间稳定性。isotonic 在小样本下更容易过拟合。[校准说明](https://scikit-learn.org/stable/modules/calibration.html)
- 校准数据保留自然正例率和业务抽样分布；类别权重仅在模型训练路径中配置。
- 类别权重作为超参数，包含权重为 1 的配置；LightGBM 可选 `scale_pos_weight`，明确与其他权重的组合关系。官方提示不平衡权重会影响个体概率估计。[LightGBM接口说明](https://lightgbm.readthedocs.io/en/stable/pythonapi/lightgbm.LGBMClassifier.html)
- 使用 `CalibratedClassifierCV` 时显式提供满足约束的划分，或校准已经冻结的模型；其默认分类交叉验证为 `StratifiedKFold`。[接口说明](https://scikit-learn.org/stable/modules/generated/sklearn.calibration.CalibratedClassifierCV.html)
- 校准器拟合和警报策略选择使用已指定的不同用途数据；校准后再次检查预算附近的分数排序与并列情况。

验收：保存校准器、拟合数据范围、原始分数定义、Brier Score、校准曲线及分箱事件数；测试数据的标签未参与拟合或选择。

### 4.5 预处理：为两种模型明确各自路径

对应原设计第 5、7.1 节及实施待办 D、E。

| 项目 | 逻辑回归 | LightGBM |
| --- | --- | --- |
| 数值缺失 | 训练集拟合插补，并保留缺失指示 | 使用原生数值缺失处理，并保留质量字段 |
| 数值缩放 | 在管道中拟合标准化或稳健缩放 | 保留合法数值尺度 |
| 类别特征 | 训练词表、One-Hot、明确未知处理 | 声明原生类别列，保存训练类别映射 |
| 非法值 | 依据单位和物理规则转换为缺失 | 同样执行数据质量规则 |
| 极端值 | 保留真实退化信号；如截尾，参数仅在训练集拟合 | 保留真实退化信号，按验证结果决定处理方式 |

LightGBM 对 pandas 类别输入中的未见类别会按缺失处理，因此额外输出未知类别标志；需要显式未知类别时，训练阶段先定义类别归并和缺失的不同含义。[官方说明](https://lightgbm.readthedocs.io/en/stable/Advanced-Topics.html)

验收：所有拟合统计量来自训练路径；批量推理加载相同处理器和特征模式；未知值、缺失值及非法值均有可观察结果。

### 4.6 SHAP：明确归因对象与输出空间

对应原设计第 9 节及实施待办 G。

- 指定解释的模型、输出空间、背景数据、背景抽样版本及基准值。
- 首版采用 `TreeExplainer` 解释 LightGBM 的原始分数，另外展示校准后的风险概率。
- 原模型归因的加和关系对应原模型的指定输出；外接校准器后，最终概率需要针对完整预测函数解释，或采用经验证的专门转换。
- 固定原因码映射及特征单位，将关键因素按推高、降低风险展示；相关的滚动特征可在展示层归组。
- 背景数据取自训练路径，验证解释加和关系，并为成功检出、误报和漏报各保存案例。

`TreeExplainer` 支持不同输出空间，概率输出存在与特征扰动方式相关的约束，实现时按锁定版本验证。[SHAP接口说明](https://shap.readthedocs.io/en/latest/generated/shap.TreeExplainer.html)

## 5. 工程选型建议

当前项目已经采用 Python 3.12、uv、pandas、PyArrow、scikit-learn、LightGBM 和 SHAP，建议继续使用，并将这些已落实的选择同步到设计文档。

| 环节 | 建议选型 | 需要固定的内容 |
| --- | --- | --- |
| 环境 | Python 3.12 + uv | Python具体版本、`uv.lock`、操作系统及主要运行参数 |
| 数据存储 | pandas + PyArrow/Parquet | 字段类型、单位、时区、表间关系；CSV作为查看与交换格式 |
| 特征处理 | 共享时点特征构建器 + 模型各自的 Pipeline/ColumnTransformer | 特征模式、训练词表、插补与缩放参数 |
| 模型训练 | LogisticRegression + LightGBM，优先使用CPU | 随机种子、线程数、调参空间、早停数据用途 |
| 校准 | sigmoid默认候选，isotonic扩展比较 | 分数输入定义、校准数据版本和评估结果 |
| 解释 | SHAP TreeExplainer + 原因码 | 归因输出空间、背景数据和原因码版本 |
| 推理 | 批量评分CLI | 输入输出模式、批次标识、幂等键和失败记录 |
| 实验与产物 | 每次运行独立目录，配置与指标使用JSON/YAML/CSV | 模型、预处理器、校准器、警报策略、划分清单、代码版本和数据指纹 |

CPU方案是否足够，以本项目实际训练和全量批量评分耗时确认。出现运行耗时或并发瓶颈后，再评估GPU或服务化部署。

每条预测建议保存：`snapshot_id`、`installation_id`、飞机、部件、评分批次、原始分数及类型、校准风险、最终警报、容量延后原因、数据质量、主要原因码，以及模型、特征、校准器、策略和数据版本。

冷启动和降级输出记录所用方法、历史覆盖和关键数据状态；历史覆盖标志与模型概率不确定性分别定义。监控沿用输入、输出及标签成熟后的结果三类指标，并保存发布、审批和回滚所需产物。

## 6. 建议实施顺序

- [ ] 将本审阅中的模型角色写入设计第 7.1 节，并统一待办中“CatBoost 或 LightGBM”的表述：首版采用 LightGBM，CatBoost 为扩展候选。
- [ ] 固定评分轮次、装机区间、循环口径、特征可用时间和标签成熟条件。
- [ ] 实现连通组规模诊断、自定义联合划分清单和泄漏断言。
- [ ] 固定训练、调参、校准、策略选择和最终测试的数据用途。
- [ ] 实现两条预处理路径，完成逻辑回归与 LightGBM 的有限调参比较。
- [ ] 完成校准、每轮预算控制、重复警报规则和按时间回放。
- [ ] 根据验证误差分析决定是否增加 CatBoost；加入时复用相同外层划分和业务指标。
- [ ] 在验证阶段确定最终模型、校准器与警报策略，再执行冻结测试。
- [ ] 完成 SHAP 输出空间检查、原因码和代表性案例。
- [ ] 保存可加载产物，在干净环境复现数据处理、训练、评估和批量预测。

测试门槛继续采用事件级召回率至少 80% 和约定口径下每 100 个部件最多 5 次警报。采用逐轮硬预算时，同时核验每轮上限。未达标的结果记录为失败实验；后续模型改进在新的独立最终评估上验证。
